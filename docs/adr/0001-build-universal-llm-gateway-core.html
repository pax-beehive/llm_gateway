Architecture Decision Record · 0001

构建一个 Responses-first 的 Go Universal LLM Gateway

面向中国客户出海：一个 OpenAI-compatible 接口，一套跨国内外 Provider 的模型路由，以及可审计、可控成本的全球 Responses 状态与 Prompt Cache Protection。

● Proposed 2026-08-23 Go 1.26.x Chat + Responses + SSE
核心判断：统一用户体验，但不伪装 Provider 能力完全相同；正确性放进 Response Store，Prompt Cache 只作为可丢弃的加速层；主动缓存保护必须按预期净收益决策。

我们决定做什么

1

Responses-first Core

内部使用 typed item/event canonical model。Chat Completions 是适配层，不是内部真相。

2

Capability-aware

每条 Model Route 明确标记 native、translated 或 unsupported，绝不静默丢字段。

3

Home-region State

状态型请求回 Home Region 单写；区域内强一致，跨区域异步复制，避免 split brain。

4

Streaming P0

Chat 和 Responses 均支持 SSE；首个可见事件之后固定 Provider，不能透明 fallback。

5

Cache Protection

预测 cache-compatible continuation，并在预算和 ROI 门槛内选择性续租 Provider Prompt Cache。

6

Provable FinOps

区分普通缓存折扣、估算保护收益和实验验证收益，而不是展示一个不可验证的“省钱数字”。

总体架构

复杂性被收进少数深模块；Public Transport、Provider Adapter 和存储实现都可替换，但不会把细节泄露给调用方。

核心接口形状

type ResponseExecutor interface {
    Execute(context.Context, CanonicalRequest) (EventStream, error)
}

type CacheProtector interface {
    Inspect(context.Context, CacheAnchor) CacheCapability
    Refresh(context.Context, CacheAnchor) (RefreshResult, error)
}

Provider Adapter 负责 wire schema、事件转换、cache breakpoint、usage 和错误；Response Runtime 负责生命周期、attempt、幂等、持久化以及首字节后的重试约束。

Responses 状态与全球一致性

权威写入

  • 区域内 PostgreSQL multi-AZ，同步 durable commit。
  • Response、items、attempt、revision、usage 和 outbox 同事务。
  • 状态通过 CAS 单调推进，并由 execution epoch/fencing 防旧 Worker 写回。

全球行为

  • 无状态请求可以全球 failover。
  • 状态型请求路由回 Home Region。
  • 跨区异步复制；DR 必须显式 promotion。
  • Home Region 故障时宁可短暂 503，也不接受冲突写入。
Quorum 属于 Response Store，不属于 cache。 Redis、Provider KV cache 和 Gateway Response Cache 都可以 miss、evict 或重建。

Streaming 是第一阶段能力

Interactive chat、coding、reasoning 与 agent tool progress 依赖较低的感知延迟。第一版支持实时 SSE 和最终 Response 落库，但不承诺全球 token-by-token durable replay。

第一版包含

  • 规范化 typed events 与单调 sequence
  • flush、keepalive、backpressure、idle timeout
  • 最终 usage reconciliation
  • client disconnect cancellation
  • 首个可见 event 后 provider pinning

后续增强

  • 区域内短期 durable Event Journal
  • starting_after 断点恢复
  • background response + polling/webhook
  • 独立的 Realtime WebSocket/WebRTC contract

三个缓存概念必须分开

概念存储什么一致性失败行为
Response StoreResponse、Conversation、items、状态、账本Home Region 强一致不可用时拒绝状态写入
Prompt CacheProvider 侧 exact-prefix KV/tensorBest effortMiss 后正常 prefill
Gateway Response Cache已完成答案的可选副本可丢弃Miss 后调用 Provider

Gateway Response Cache 默认关闭，只允许明确可缓存的 stateless workload；Prompt Cache 不复用答案，只降低相同前缀的输入处理成本。

功能亮点：Predictive Cache Protection

把 Provider Prompt Cache 看成一个有路由身份、有预估过期时间、但不保证存在的 Cache Lease。真正预测的是下一次 cache-compatible request 的时间概率，而不是“任务是否已经结束”。

Refresh 决策 Expected Net Saving = Pcontinue × (Cold Cost − Hit Cost) − Refresh Cost − Forecast Cost − Route-lock Cost

保护策略约束

  • 默认关闭，Tenant 或请求显式开启
  • 限制 max spend、refresh 次数和保护时长
  • 真实请求到达后取消 pending refresh
  • Home Region 故障时直接放弃优化
  • 严格固定 provider/model/credential/region/cache key
  • refresh 不进入用户 Conversation/Response Chain
  • 有副作用的 hosted tools 默认不 refresh
  • 上游结果不确定时记录 uncertain，不盲目重试

阶段Provider策略

省钱必须可以解释和验证

Observed

Provider 明确报告的 cached tokens × 当前 price snapshot 的折扣。说明发生了缓存命中，但不归因给保护功能。

Estimated

发生在原始 expiry 之后、refresh expiry 之前的 Protected Hit，减去 refresh、预测和路由机会成本。

Validated

Eligible session 随机 treatment/holdout 的增量成本差，校准预测误差和 Provider 自然延长缓存的影响。

产品界面展示 estimated net savings，只有经过 holdout 校准后才展示“由 Cache Protection 带来的验证节省”。

面向客户的功能亮点

China → Global

国内外模型、区域 credential、data residency 和出海网络路径成为一等能力，而不是 generic OpenAI proxy 的附加项。

Universal, but honest

统一 contract 与 SDK 体验，同时公开能力差异、translation 和降级行为。

Responses-native

支持 stateless、Response Chain 和 Conversation，不强迫所有调用共享一个 session ID。

Cache-aware routing

在 compliance、health 和 budget 约束内保留 route affinity，而不是只按最低单价路由。

Predictive savings

对值得保护的长上下文主动续租，并用预算和 Expected Value 防止 heartbeat 反而烧钱。

Auditable FinOps

每次 attempt、cache read/write、price snapshot、refresh 和 protected hit 都可追溯。

建议交付顺序

  1. Canonical contract
    Typed items/events、Capability Profile、OpenAI-compatible transports 与 fixtures。
  2. Stateless execution
    SSE、usage、attempt、provider error 与首字节后的固定路由。
  3. Durable Responses
    Response Chain、Conversation、Home Region、idempotency、CAS 与 tombstone。
  4. MaaS control plane
    Tenant policy、quota、price snapshot、ledger 与多维 routing。
  5. Cache observability
    统一 provider cache usage 与 cache-aware affinity，但先不主动 refresh。
  6. Protection shadow mode
    预测 continuation、计算 EV、记录假想决策，不产生额外模型调用。
  7. Anthropic canary
    最多一次 refresh、严格预算、随机 holdout、Savings Ledger。
  8. Provider expansion
    只有 provider-specific conformance 与经济测试通过后才加入新 refresh adapter。

明确接受的取舍

  • 比 thin proxy 有更多 canonical modeling，但 provider 复杂度不会扩散到每个调用方。
  • Home Region 故障时，状态型写入可能暂时不可用，以换取无 split brain。
  • Provider capability、价格和 cache contract 必须版本化并持续验证。
  • Cache Protection 带来预测、隐私、调度和归因责任，因此默认关闭并渐进发布。

第一阶段非目标

No 全球 active-active Conversation 写入　No 所有 hosted tools 打平　No Realtime audio　No 默认 semantic response cache　No 流式输出后透明 fallback　No 全球 token-by-token replay
